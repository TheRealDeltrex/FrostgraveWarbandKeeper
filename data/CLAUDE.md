# data/ — reference JSON

Loaded through `game_content.py`. Warband saves, portraits and uploads live in the user data
dir, never here. **Read the `game-data-files` skill before editing anything here** (extractor
reverts, item restrictions in code, spell-name collisions, sourcing from the rulebook
PDFs, folder in `CLAUDE.local.md`).

- **`common_items.json`** — Core Rules price list (potions, magic weapons/armour, magic items,
  grimoires and scrolls at p.104 prices); feeds the Shop and the loot picker's "Common items".
  Regenerated by `scripts/extract_common_items.py`: fix the script, not the JSON.
- **`supplement_item_prices.json`** — the same for supplements, **keyed by `(source, name)`**
  (`scripts/extract_supplement_prices.py`; docstring covers sale estimates and unpriced books).
  The key travels as `"Source::Name"` in form fields and a vault entry's `catalog_key`
  (`warband_store.supplement_catalog_key()`); `shop_prices()` takes that or a bare Core name.
- **Core Rules reprice what they reprint** (Construct Oil, Construct Hammer, Ring of
  Transference). The extractor drops supplement rows priced in `common_items.json`, and
  `shop_sale_price()` reads Core first. Where two *supplements* share a name, a found item
  gets no price suggestion rather than a guess.
- **`magic_items.json`, `expansion_rules.json`, `ghost_archipelago.json` are the source of
  truth**, ahead of the reference docs; `scripts/extract_expansion_content.py` only adds. Edit
  them as textual insertions — parts are hand-compacted onto single lines, so a `json.dumps()`
  round-trip reformats hundreds of lines. After a run that wrote, keep only the additions.
